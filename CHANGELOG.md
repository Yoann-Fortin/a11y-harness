# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Marketplace and plugin manifests (`a11y-harness` 0.1.0).
- Playground with a login form sample component, built test-first against WCAG 2.2 with a 100% mutation score: labelled fields, autocomplete tokens, a password visibility toggle with its own show and hide icons and an exposed state, errors linked to the empty fields and announced to assistive technologies, again on each submission even when the errors have not changed.
- `CLAUDE.md` with the project layout and commands, and a rule file scoped to the playground tests.
- MIT licence.
- Root pnpm workspace with the plugin's development tools (Vitest, Stryker, Biome, TypeScript), a single lockfile and a single Biome configuration.
- `a11y-check` hook (PostToolUse on Write and Edit of `.tsx` and `.jsx` files): runs the linter (Biome or ESLint) and the related tests (Vitest or Jest) that the component's package depends on, skips a package that uses none of them, offers accessibility tests written with `a11y-test-writer` when no test covers the component, to write only with the agreement of the user, asks to keep failing existing tests unless they freeze an inaccessible behaviour, which needs the user's agreement and an explanation, asks for an audit with `a11y-component-audit` when the file holds a form, ignores the variants written in an `a11y-variants` folder, leaves out the tests of the other standard, and asks Claude to fix the findings through `decision: "block"` with a JSON report, free of colour codes. Runs on Node 22.18 or later, without a build step.
- `a11y-check` runs Playwright Test when the package depends on it: the spec files named after the edited component, in the family of the standard, with a JSON report free of colour codes. `verify-tests` judges a test file with the first test runner of the package that runs it, so that a Jest project checks its Playwright spec files too.
- `verify-tests` reports `no-test-runner` when the package names a test runner it has not installed, instead of rejecting every variant.
- The audit skill rules on nothing beyond the form, and settles contrast, visible focus or target size from the component's browser tests when it has some. The test writer's method names its stylesheet variants and every test runner `verify-tests` uses.
- `a11y-check` no longer leaves alone a package without a test runner: it asks Claude to offer the team the browser mode of Vitest or Playwright Test, and to install either only with their agreement.
- `reviewer-guard` hook (PreToolUse on Bash): keeps the `a11y-reviewer` agent read-only by denying any command but the audit skill's `node` commands and `git diff`, `git log` or `git show`, run on their own and without `--output`.
- `answer-guard` hook (Stop): sends Claude's final answer back once when it cites a criterion of the criteria table that the inventory of the audited form did not open, reading the inventories in the session's transcript and in its agents' transcripts.
- `standard` plugin option: `wcag-2.2` (default) or `rgaa-4.1.2`.
- `a11y-component-audit` skill: audits a form, and the components rendered inside it, against WCAG 2.2 AA or RGAA 4.1.2 from the official texts it bundles (W3C WCAG 2.2 and ACT rules mapping, DINUM RGAA 4.1.2 criteria and methodology). A `lookup` command quotes a criterion, and a `validate` command rejects any report whose criterion, level, title or evidence does not match those texts. An `inventory` command lists the form elements of a component and the criteria each one opens, from a criteria table whose signals are tested on examples, and `validate` rejects a report that leaves one of them out, or that cites a criterion of the table that the inventory did not open. A forms checklist records rulings checked against the same sources, and a React reference the defects that come from how React renders, such as a repeated error that is not announced again. Evaluation cases under `evals/`.
- `a11y-test-writer` skill: writes the accessibility tests of a component for WCAG 2.2 or RGAA 4.1.2 with Testing Library, in the family of each requirement, before the component is fixed. A `verify-tests` command runs those tests on one variant of the component per conforming technique and on the faulty component, and reports every variant they misjudge. Evaluation cases under `evals/`.
- `a11y-test-writer` writes the tests that depend on rendering, such as visible focus, target size, contrast and label position, in a browser when the package runs tests in one, with the browser mode of Vitest or Playwright Test, and checks them against variants of the stylesheet. Evaluation case `write-browser-tests-wcag`.
- `a11y-reviewer` agent: reviews the forms of several components, a folder or the changes of a branch with the audit skill, without changing any file.
- GitHub Actions workflow: type checking, lint and tests of the plugin on Node 22.18 and 24, validation of the marketplace and plugin manifests, tests and build of the sandbox, and a 100% mutation score in both places.
- README: installation, choice of standard, the two verdicts of the playground, architecture, evaluations, limits and roadmap.
- Browser tests in the playground: a `browser` Vitest project runs the `*.browser.*test.tsx` files in Chromium through Playwright, next to the `jsdom` project, and both leave out the tests of the other standard.
- A stylesheet for the playground login form, as a design would hand it over, with the eye icon inside the password field.
- Browser test for the login form against WCAG 2.5.8: every target is at least 24 by 24 CSS pixels, or spaced as the criterion allows. The design's 16 pixel eye icon failed it, and its button now has a 4 pixel padding. Stryker leaves the browser tests out, since it does not mutate CSS.
- Browser test for the login form against WCAG 2.4.7 and RGAA 10.7: every element reached with the Tab key looks different while it has the focus, whatever the technique. The design's `outline: none` on the buttons failed it, and the rule is gone.
- Browser test for the login form against WCAG 1.4.3 and RGAA 3.2, with axe-core: its text has enough contrast before and after a submission with errors. The design's light grey labels, light red errors and white on indigo button failed it, and their colours are darker.
- WCAG-only tests for the login form (3.3.2, each field named by text shown on the page), written from the first cycle.
- RGAA-only tests for the login form: 7.5.2 (errors announced as an alert), 11.10.6 (a malformed email address gets an error naming the field, so the form turns off the browser's native validation), and 11.10.1 and 11.10.2 (required fields shown before submission), which the form fails on purpose. Under WCAG 2.2 the hook only asks for the audit of the form, under RGAA 4.1.2 it also names the failing tests and their criterion.
